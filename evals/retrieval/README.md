# 建筑资料检索基线

在项目根目录运行 `.\.venv\Scripts\python.exe -m evals.retrieval_baseline`。命令离线调用工作台使用的 `search_current`，数据使用本目录下冻结的演示条款。工作台可以继续处理新文档，测评仍可复现。

`corpus.jsonl` 收录两个项目的 7 个条款片段，来自项目内虚构的会审纪要归档流程、两份材料报审流程和资料移交流程 PDF。会审流程的 R02 草稿也在语料内，供检验版本过滤。每条保存原条款 ID、检索文本、项目与版本状态。记录顺序沿用发布索引，同分时会影响排序。

`questions.jsonl` 包含 9 道有明确依据的题和 3 道在这份语料中缺少依据的题。每道有依据题标注一个足以回答的条款。P03 与 P04 问法相同，QL01 的材料报审时限为 2 个工作日，HT02 为 5 个工作日。P07 与 P09 用“交接单”指代文件里的“移交清单”。

- Hit@1 和 Hit@3 分别计算正确条款排第一和进入前三的题数，占 9 道有依据题的比例。
- MRR@3 取每道有依据题的排名倒数后求平均。正确条款未进前三时，该题计 0。
- 对全部 12 道题，逐条检查返回的前三个候选是否来自当前项目且已生效，并统计异常引用出现次数。
- 对 3 道缺依据题，单独记录是否仍召回了相关候选。例如会审纪要的归档职责条款能被召回，但它没有给出归档天数。模型能否依据这些候选正确拒答，需要另外评估。

### 首次测量

题集与语料指纹为 `8dee86ff2c09`。当前检索按相邻双字符的重合数排序，9 道有依据题的 Hit@1 为 6/9，Hit@3 为 8/9，MRR@3 为 0.778。12 道题的前三候选共出现 0 次越界或未知引用，3 道缺依据题都返回了相关候选。

P06 的第一条是引言，给出明确时限的 §2.1 排第二。P07 使用“交接单签字收下以后，最晚何时存好”，没有召回任何条款。两题对应的现行业务资料相同，可以用来观察排序和换词对检索的不同影响。

比较检索改动前后的指标时，使用同一题集与语料指纹。此基线用于定位小样本中的问题，对真实项目效果的评估还需要独立的员工问题和人工标注。

### 混合检索对照

模型准备完成后，运行 `.\.venv\Scripts\python.exe -m evals.retrieval_baseline --compare`。该命令固定执行字面检索与 BGE 混合检索，两次使用相同的候选数、语料和标注，并列出每道有依据题的条款名次。

| 指标 | 字面检索 | 字面与 BGE 混合 |
| --- | ---: | ---: |
| Hit@1 | 6/9 | 9/9 |
| Hit@3 | 8/9 | 9/9 |
| MRR@3 | 0.778 | 1.000 |
| 越界或未知引用出现次数 | 0 | 0 |
| 缺依据题有候选 | 3/3 | 3/3 |

这次测量使用指纹 `8dee86ff2c09`。P07 从无候选变为第 1 名，P06、P09 从第 2 名升到第 1 名。N02 问延迟归档的罚款金额，混合检索返回了归档时限条款，金额依然缺乏依据。该实验测量检索排序，未调用生成模型。

### 现行条款能否支持答复

在项目根目录运行 `.\.venv\Scripts\python.exe -m evals.answer_quality`。这次用相同冻结语料和混合检索，为每道有候选的题调用一次项目现有的 DeepSeek 证据选择器，整套最多调用 12 次。模型接收问题和候选原文，评分程序使用人工标注。只复查个别结果可用 `--case P07 N02`。

9 道有依据题要求选中标注条款，3 道缺依据题要求拒答。程序单列有候选时模型仍然正确拒答的数量。候选范围异常时整轮中止。服务错误或响应解析失败时会报告出错题号与已完成题数。完整运行且全对的退出码为 0，存在判断错误时为 1，运行中断时为 2。
